# ПрофНавигатор AI — техническая спецификация проекта

> Этот документ — стартовый бриф для разработки в Claude Code. Он описывает архитектуру, логику,
> схему данных, промт для YandexGPT и план работ. Передайте его целиком Claude Code как первое
> сообщение в новом репозитории.

## 1. Суть продукта

Веб-приложение, которое с помощью ИИ (YandexGPT) помогает пользователю подобрать профессию,
подходящую его склонностям, качествам, опыту, региону проживания и перспективам рынка труда
на горизонте 5 лет.

Две категории пользователей:
- **Подростки 13–17 лет** — фокус на выявлении склонностей и направлений обучения.
- **Взрослые** — фокус на опыте, навыках, причинах смены профессии и плавном карьерном переходе.

Подзаголовок: «ИИ помогает определить наиболее подходящие профессии на ближайшие 5 лет с учетом
ваших способностей, опыта, региона проживания и рынка труда.»

Дизайн: светлые тона, бирюзовые акценты (`#1D9E75` / `#0F6E56` как основной акцент, `#E1F5EE`
как светлый фон-подложка для карточек). Минимализм, крупная кнопка «Начать анализ» на главном
экране, ниже — две карточки категорий.

## 2. Технологический стек

| Слой | Технология | Обоснование |
|---|---|---|
| Frontend | Next.js 14+ (App Router), TypeScript, Tailwind CSS | SSR/SEO, единая кодовая база с backend через API routes при необходимости, лёгкое масштабирование |
| Backend | Node.js + TypeScript, Yandex Cloud Serverless Containers (Express/Fastify) | Изоляция секретов, вызовы YandexGPT, генерация файлов, будущая авторизация/оплата |
| БД | Yandex Managed Service for PostgreSQL | Хранение персональных данных строго на территории РФ (152-ФЗ) |
| Секреты | Yandex Lockbox | Хранение API-ключа сервисного аккаунта вне кода и переменных окружения в открытом виде |
| Файлы отчётов | Yandex Object Storage (S3-совместимое) | Хранение сгенерированных PDF/DOCX, временные ссылки на скачивание |
| Auth (будущее) | NextAuth.js / собственная реализация на базе email+OTP | Регистрация по почте |
| Оплата (будущее) | ЮKassa / CloudPayments | Локальные платёжные провайдеры, интеграция с РФ |
| Аналитика (будущее) | Yandex Metrika + собственная таблица events в PostgreSQL | Сбор данных о прохождении теста |

**Важно по безопасности ключа:**
- Секретный ключ (`key_id` + `secret`) НИКОГДА не передаётся на frontend и не попадает в клиентский
  JS-бандл.
- Все вызовы к Foundation Models API идут только с backend.
- Ключ следует перевыпустить в консоли Yandex Cloud (IAM → сервисные аккаунты → статические
  ключи доступа), так как исходный ключ был показан в открытом чате.
- Хранить ключ через Yandex Lockbox, backend читает секрет через Lockbox SDK при старте
  контейнера, а не через `.env` в открытом виде в репозитории.
- Обязательно добавить `.env`, `.env.local` в `.gitignore`.

## 4. Логика вопросов (динамический опрос)

### 4.1 Общая механика
- Вопросы показываются **сериями по 3–5 штук**, не все сразу.
- После каждой серии — запрос следующей серии, которая зависит от предыдущих ответов
  (branching). Логика ветвления реализуется на backend (простое дерево правил + при
  необходимости обращение к YandexGPT для генерации уточняющего вопроса на "серых" ответах).
- Цель — минимальное количество вопросов до уверенного результата (обычно 4–6 серий).
- Последний блок — **«ИИ-диалог»**: 2–4 открытых вопроса в свободной форме.
- Перед финальной отправкой — экран **«Проверьте ваши ответы»** с возможностью
  редактирования любого ответа (включая ответы в свободной форме).

### 4.2 Общие блоки (для всех)
1. **Категория**: подросток / взрослый (выбор на главной странице).
2. **География**: страна, регион/область, тип и численность населённого пункта
   (мегаполис 1млн+ / крупный город 250к–1млн / средний город 50к–250к / малый город и ниже /
   село). Влияет на доступность профессий, уровень цифровизации, зарплатные вилки.
3. **Интересы и предметы/сферы** (multi-select, адаптируется под возраст).
4. **Тип мышления и предпочтения в работе**: работа с людьми / с данными и системами /
   с творчеством и образами / с руками и объектами / со словами и текстами.
5. **Формат работы**: офис / удалёнка / разъездной / смешанный — предпочтение.
6. **Ценности в работе** (ранжирование): доход, стабильность, творческая свобода, влияние
   на людей/общество, баланс работы и жизни, карьерный рост, интеллектуальный вызов.

### 4.3 Ветка «Подростки 13–17»
- Любимые школьные предметы / кружки, дополнительные занятия.
- Уровень уверенности в математике/языках/творчестве/технике (шкала).
- Проекты/олимпиады/хобби, где был реальный успех.
- Отношение к учебе после школы: колледж / вуз / самообразование / пока не знаю.
- Планы по языкам (для оценки международных возможностей).
- **Не задаются**: вопросы об опыте работы, стаже, прошлых должностях, доходе на текущем месте.

### 4.4 Ветка «Взрослые»
- Текущая/последняя профессия и сфера.
- Стаж работы (диапазон).
- Что нравилось / не нравилось в текущей профессии (обязательно — ключевой сигнал).
- Причина желания сменить профессию (multi-select + свободный комментарий).
- Уровень образования и наличие профильных сертификатов.
- Готовность к переобучению: сроки (до 3 мес / до года / более года) и формат (курсы,
  вуз, самообучение, менторство).
- Финансовая "подушка"/готовность к временному снижению дохода при смене (диапазон, не
  точные цифры дохода — только категория).
- Семейное положение/нагрузка (влияет на риск-профиль и скорость перехода) — опционально,
  можно пропустить.

### 4.5 Финальный блок — «ИИ-диалог» (свободная форма, для всех)
Примеры вопросов (выбираются адаптивно, 2–4 из пула):
- «Расскажите о случае, когда вы испытывали настоящее удовольствие от работы или учёбы.»
- «Представьте, что деньги не имеют значения. Чем бы вы занимались?»
- «Опишите задачу, которая давалась вам легко, когда другим — тяжело.»
- «Что бы вы никогда не согласились делать, даже за большие деньги?»
- «Кем вы восхищаетесь профессионально и почему?»

Эти ответы передаются в промт YandexGPT **дословно**, без интерпретации на фронтенде.

### 4.6 Логика ветвления (пример правил)
```
IF категория == "подросток" → скрыть блок "Опыт работы"
IF ответ на "формат работы" == "разъездной" AND населённый_пункт == "село" →
    уточняющий вопрос про готовность к переезду
IF ценности содержат "высокий доход" AND текущая_сфера == "творческая" →
    уточняющий вопрос: "что важнее — стабильный доход или самореализация" (dilemma-вопрос)
IF заполнено < 70% уверенности классификатора после базовых блоков →
    сгенерировать 1 доп. вопрос через YandexGPT на основе неоднозначных ответов
```

## 6. Системный промт для YandexGPT (полный, для системного сообщения)

```
Ты — профессиональный карьерный консультант, аналитик рынка труда и специалист по
профориентации с 20-летним опытом. Ты работаешь с данными, собранными через
структурированный опрос пользователя сервиса «ПрофНавигатор AI».

ВХОДНЫЕ ДАННЫЕ придут в формате JSON со следующими блоками: meta, geo, profileCommon,
adultSpecific ИЛИ teenSpecific, aiDialogue (ответы в свободной форме).

ПРОАНализируй:
- способности и склонности пользователя
- имеющийся опыт (если есть)
- психологические особенности и тип мышления
- сильные стороны
- слабые стороны и зоны риска
- регион проживания и уровень цифровизации инфраструктуры в нём
- размер населённого пункта и его влияние на доступность профессий и удалённой работы
- востребованность профессий именно в этом регионе
- возможность удалённой работы для рассматриваемых профессий
- вероятность автоматизации/замены ИИ для каждой профессии на горизонте 5 лет
- перспективы и рост спроса на профессию в ближайшие 5 лет
- возможный диапазон дохода (в привязке к региону, не завышай ожидания)
- скорость входа в профессию (сколько месяцев/лет до первой работы)
- сложность обучения и требуемый уровень базовой подготовки
- вероятность и скорость карьерного роста внутри профессии
- соответствие ценностям, которые пользователь указал как приоритетные

ОГРАНИЧЕНИЯ:
- Не рекомендуй профессии, которые заведомо быстро исчезают или уже сокращаются
  (обоснуй одним предложением, почему конкретная профессия не рекомендована, если это
  уместно).
- Не предлагай профессии, прямо противоречащие указанным интересам или явно
  выраженным "красным линиям" пользователя (например, если человек написал, что никогда
  не будет работать с продажами — не предлагай продажи).
- Не давай юридических или медицинских консультаций.
- Не выдумывай точные цифры зарплат — используй диапазоны и указывай, что это ориентир.
- Если пользователь — подросток (13-17 лет), никогда не ссылайся на опыт работы,
  говори только о направлениях обучения, кружках, факультативах, олимпиадах и вузах/ссузах.
- Тон — поддерживающий, уважительный, без давления и без излишней критики.
- Отвечай только на русском языке.
- Верни ответ СТРОГО в формате JSON согласно схеме ниже, без preamble, без markdown-разметки,
  без пояснений до или после JSON.

СХЕМА ОТВЕТА (строго соблюдай ключи):
{
  "personalitySummary": "string, 1-2 страницы текста",
  "keyStrengths": ["string", "..."],
  "possibleLimitations": ["string", "..."],
  "psychologicalProfile": "string, развёрнутый абзац",
  "topProfessions": [
    {
      "title": "string",
      "whyItFits": "string",
      "entryDifficulty": "низкая|средняя|высокая",
      "incomeRangeDescription": "string",
      "remotePossibility": "высокая|средняя|низкая",
      "growthProspect": "string",
      "automationRiskIn5Years": "низкий|средний|высокий",
      "demandProbabilityIn5Years": "низкая|средняя|высокая"
    }
  ],
  "alternativeProfessions": [{ "title": "string", "shortReason": "string" }],
  "transitionPlan": {
    "month1": "string",
    "month2": "string",
    "month3": "string",
    "sixMonths": "string",
    "oneYear": "string"
  },
  "whatToLearn": [{ "topic": "string", "suggestedFormat": "string" }],
  "existingSkills": ["string", "..."],
  "missingSkills": ["string", "..."],
  "detailedReasoning": "string, подробное объяснение почему именно эти профессии",
  "finalRecommendation": "string, итоговый краткий вывод и напутствие"
}

topProfessions должен содержать ровно 10 профессий, отсортированных по релевантности,
с явным приоритетом профессиям с растущим или стабильным спросом на горизонте 5 лет.
```

Backend валидирует ответ на соответствие JSON-схеме (например через `zod`) перед
рендерингом отчёта и сохранением в БД. Если YandexGPT вернул невалидный JSON — сделать
один повторный запрос с уточнением "верни строго валидный JSON".

## 7. Структура итогового отчёта (маппинг на экран + документ)

1. Краткое резюме личности (`personalitySummary`)
2. Главные сильные стороны (`keyStrengths`)
3. Возможные ограничения (`possibleLimitations`)
4. Психологический профиль (`psychologicalProfile`)
5. ТОП-10 профессий (`topProfessions`) — карточка на каждую: название, почему подходит,
   сложность входа, доход, удалёнка, перспектива, риск автоматизации, вероятность
   востребованности через 5 лет
6. Альтернативные профессии (`alternativeProfessions`)
7. План перехода по месяцам (`transitionPlan`)
8. Что изучать (`whatToLearn`)
9. Какие навыки уже есть (`existingSkills`)
10. Каких навыков не хватает (`missingSkills`)
11. Подробное объяснение выбора (`detailedReasoning`)
12. Итоговая рекомендация (`finalRecommendation`)

Отчёт доступен на экране сразу после генерации и как файл для скачивания в PDF и DOCX
(генерация на backend: `docx` npm-пакет для Word, `puppeteer`/`pdf-lib` — рендер HTML-шаблона
отчёта в PDF).

## 8. Черновая схема базы данных (PostgreSQL)

```sql
users (
  id uuid pk,
  email text unique null,        -- заполняется после внедрения регистрации
  created_at timestamptz
)

sessions (
  id uuid pk,
  user_id uuid null references users(id),
  category text check (category in ('teen','adult')),
  geo jsonb,
  status text check (status in ('in_progress','completed')),
  created_at timestamptz,
  completed_at timestamptz null
)

answers (
  id uuid pk,
  session_id uuid references sessions(id),
  question_key text,
  question_text text,
  answer jsonb,
  answer_type text check (answer_type in ('choice','multi_choice','ranking','free_text')),
  created_at timestamptz
)

reports (
  id uuid pk,
  session_id uuid references sessions(id),
  raw_llm_response jsonb,
  pdf_object_key text null,
  docx_object_key text null,
  created_at timestamptz
)

-- задел на будущее
payments (
  id uuid pk,
  user_id uuid references users(id),
  session_id uuid references sessions(id),
  amount numeric,
  currency text default 'RUB',
  status text,
  provider text,
  created_at timestamptz
)

events (
  id uuid pk,
  session_id uuid null,
  user_id uuid null,
  event_name text,
  payload jsonb,
  created_at timestamptz
)
```

## 10. План разработки (для Claude Code, по шагам)

1. Инициализация репозитория: Next.js + TypeScript + Tailwind, структура `apps/web`,
   `apps/api` (или единый Next.js с API routes на старте — можно упростить до монолита
   Next.js на MVP, вынести backend в отдельный сервис позже при росте нагрузки).
2. Главная страница по макету раздела 9.
3. Компонент опроса: движок сериями вопросов + сохранение прогресса в состоянии/БД.
